# Портфолио → график самбарын дизайны хэрэгсэл

Төлөв: **чиглэлийн санал** — хэрэглэгчийн батламж хүлээж байна. Код бичээгүй.
Огноо: 2026-08-24 · Бэлтгэсэн: STU

## 1. Юу болох гэж байгаа вэ

Хэрэглэгчийн үг: «Бид төслийн ГРАФИК САМБАР бэлдэнэ… бэлэн загвар бүхий
самбарын гарчгийн дизайн байна. Хэрэглэгч түүнээс сонгоход портфолио самбарын
толгой гарчиг үүсдэг байна. CGA дээр боловсруулсан ерөнхий төлөвлөгөөний
лэйрүүдийг мэдэрч автоматаар график дүрслэлд оруулдаг байна… ногоон
байгууламжийг мэдэрч хатч биш бодит зүлэгний паттерн өгдөг болно… портфолио
бол ДИЗАЙНЫ ХЭРЭГСЭЛ болж хөгжих учиртай.»

Өнөөдрийн Портфолио бол **хуудасны жагсаалт ба тэдгээрийг нэгтгэгч**: элемент
бүр бүтэн хуудас эзэлж, дараалуулаад PDF болдог. Зорилго нь **самбарын
дизайнер**: нэг самбар дээр олон элемент чөлөөтэй байрлаж, зарим нь өгөгдлөөс
автоматаар зурагдана.

Энэ бол өнөөдрийн ажлыг хаях биш — **дараагийн давхарга нэмэх**.

## 2. Одоо байгаа хөрөнгө (дахин бүтээхгүй)

| Хөрөнгө | Одоо юу хийдэг | Самбарт хэрхэн үйлчлэх |
|---|---|---|
| `ProjectPortfolio` / `ProjectPortfolioItem` | элемент бүр = нэг хуудас; дараалал, нэр, тайлбар, байрлал, нуулт | **Элемент нь самбар болно** — дотроо элементүүдтэй. Curation-ы дүрмүүд утгаа хадгална |
| `PageSizeMode` (тогтмол / эх хуудасны хэмжээгээр) | PDF хуудасны хэмжээ | **Самбарын хэмжээ** — өөрчлөлтгүй тохирно |
| `PortfolioPlacement` (Fit / Cover) | зураг хуудсанд яаж багтахыг тооцоолно | **Элемент бүрийн байрлалын үндэс** — хүрээ дотор багтаах/дүүргэх нь ижил математик |
| `PortfolioPdfWriter` | хуудас бүрд нэг эх файл зурна | **Самбар бүрд олон элемент** зурдаг болж өргөжинө; PDF гаргах зам, вектор хадгалалт хэвээр |
| `PageFormatSpec` / `PageRectMm` | хуудасны мужийг мм-ээр тодорхойлно | Самбарын координатын систем — шинээр зохиох шаардлагагүй |
| **`ProjectSitePlanFeatures`** (CGA sidecar) | зам (нэр, шугам), барилга (дугаар, нэр, **төрөл**, полигон) солбицолтойгоо | **Семантик давхаргын аль хэдийн ажиллаж буй суваг** — «лэйрийг мэдрэх»-ийн үндэс энд бэлэн байна |
| `PdfSharpAlbumWriter`-ийн chrome давхарга | хүрээ, тор, гарчгийн хүснэгт зурдаг | Вектор зурах хэв маяг; загварын элементүүдэд дахин ашиглагдана |

**Гол дүгнэлт:** «давхаргын семантикийг таних» гэдэг нь тэглээс эхлэхгүй.
CGA-гаас зам, барилга нь **ангилалтайгаа** ирдэг суваг аль хэдийн ажиллаж
байна. Дутуу нь — **ногоон байгууламж болон бусад талбайн ангиллууд тэр
сувагт байхгүй** байгаа явдал.

## 3. Юуг шинээр бүтээх

### 3.1 Самбарын модель (canvas)

Самбар = мм-ээр хэмжигдэх талбай + дараалалтай **элементүүд**. Элемент бүр:
байрлал (мм), хэмжээ, эргэлт, z-дараалал, түгжээ, харагдац.

Элементийн төрлүүд (эхний багц):

- **Гарчгийн блок** — загвараас гарна (§3.2)
- **Зураг / PDF хуудас** — өнөөдрийн CadPage, Image, Document элемент энд шилжинэ
- **Төлөвлөгөөний дүрслэл** — CGA-гийн семантикаас автоматаар зурагдана (§3.3)
- **Текст** — гарчиг, дэд гарчиг, тайлбар
- **Легенд** — ашиглагдсан ангиллаас автоматаар
- **Хойд сум**, **масштабын шугам** — өгөгдлөөс (эргэлт, масштаб)
- **Хүснэгт** — үзүүлэлтийн хүснэгт (сүүлийн шатанд)

### 3.2 Гарчгийн загварын сан

Загвар = нэрлэгдсэн зохион байгуулалт: гарчиг, дэд гарчиг, лого, төслийн нэр,
огноо зэрэг талбаруудыг **хаана, ямар фонт/өнгө/хэмжээгээр** байрлуулахыг
тодорхойлно. Талбарууд төслийн бодит өгөгдлөөс автоматаар дүүрч, хэрэглэгч
зөвхөн загвараа сонгоно.

> **Хамгийн том нээлттэй асуулт:** бодит бэлэн загварууд ямар хэлбэрээр байгаа
> вэ — DWG, PDF/AI, зураг, эсвэл зөвхөн цаасан дээрх дизайн уу? Хариу нь
> загварыг **өгөгдөл болгож уншина** уу, эсвэл **дүрслэлээр нь давтаж зурна**
> уу гэдгийг шийднэ. Энэ хоёр нь өөр өөр ажлын хэмжээ.

### 3.3 Семантик → график дүрслэлийн давхарга

Оролт: ангилалтай геометр (CGA-гаас). Гаралт: тухайн ангилалд харгалзах
**дүрслэлийн загвар** — паттерн, дүүргэлт, шугамын хэв маяг, тэмдэгт.

- **Дүрслэлийн сан:** ангилал → дүрслэл. Жишээ: `greenery` → зүлэгний паттерн;
  `road` → хучилтын өнгө ба ирмэгийн шугам; `water` → усны паттерн;
  `building` → төрлөөрөө ялгаатай дүүргэлт.
- Хэрэглэгч дүрслэлийг **дарж бичих** боломжтой байх ёстой — загвар бол эхлэл,
  эцсийн үг биш.
- **Легенд автоматаар** үүснэ: самбар дээр бодитоор ашиглагдсан ангиллуудаас.

**CGA-гаас хэрэгтэй нь:** ангилалтай **полигон** (hatch биш). Одоогийн
sidecar-т зам, барилга бий; ногоон байгууламж болон бусад талбайн ангилал
нэмэгдэх ёстой. CGA агенттай яриа эхэлсэн (§6).

### 3.4 Рендерийн зам

Нэг зурах давхарга, хоёр гаралт: **PDF** (вектор, хэвлэлт) ба **зураг** (PNG —
урьдчилан харах, танилцуулга). Элементүүд мм-ээр тодорхойлогдох тул хоёулаа нэг
геометрээс гарна.

## 4. Үе шатууд

**1-р шат — Самбар ба гарчиг (эхний бодит үр дүн).**
Портфолиогийн элемент «самбар» болно; самбар дээр зураг/PDF элемент чөлөөтэй
байрлана; гарчгийн загвараас сонгоход толгой гарчиг үүснэ; PDF ба зураг гарна.
*Хэрэглэгч гарчгийн загвар сонгоод бодит самбар гаргаж чадна.* Одоо байгаа
портфолио алдагдахгүй — нэг элементтэй самбар нь өнөөдрийн зан төлөвтэй ижил.

**2-р шат — Элементийн багц.** Текст, хойд сум, масштабын шугам, хүрээ/шугам.
PFA-гийн масштабын өгөгдлөөс хамаарна (§6).

**3-р шат — Семантик дүрслэл.** CGA-гийн ангилалтай полигоноос төлөвлөгөөний
дүрслэл зурах; дүрслэлийн сан; автомат легенд. Хэрэглэгчийн жишээ (ногоон
байгууламж → зүлэгний паттерн) энэ шатанд биелнэ.

**4-р шат — Гүнзгийрүүлэлт.** Үзүүлэлтийн хүснэгт, олон самбарын цуврал,
хэрэглэгчийн өөрийн загварын сан, дүрслэлийн нарийвчилсан тохиргоо.

Шат бүр өөрөө дуусмаг: 1-р шат гармагц хэрэглэгч бодит самбар гаргаж чадна,
дараагийн шатууд түүн дээр нэмэгдэнэ.

## 5. Зарчим ба эрсдэл

- **Одоо байгаа портфолио эвдэрч болохгүй.** Нэг элементтэй самбар нь өнөөдрийн
  хуудастай ижил үр дүн өгөх ёстой; хэрэглэгчийн зохион байгуулалт, тайлбар,
  хэмжээний тохиргоо шилжилтэд хадгалагдана.
- **Загвар бол эхлэл, эцсийн үг биш.** Автомат дүрслэл ч, автомат гарчиг ч
  гараар засварлагдана — портфолиогийн бүх ажилд баримталсан зарчим: хэрэглэгч
  гар хүрсэн зүйл нь хэрэглэгчийнх.
- **Семантик эх сурвалжаас ирнэ, Studio таамаглахгүй.** Ангилалгүй геометрийг
  «ногоон байх шиг байна» гэж таамаглах нь буруу зам; ангилал CGA-гаас ирнэ.
- **Хамрах хүрээний эрсдэл:** энэ бол Illustrator биш. Зорилго нь **төслийн
  самбар** — тодорхой элементийн багц, тодорхой өгөгдлийн эх сурвалж. Ерөнхий
  зориулалтын вектор редактор болгох оролдлого хэзээ ч дуусахгүй.

## 6. Бусад программаас хэрэгтэй зүйл

**CGA (асуулт илгээсэн, хариу хүлээгдэж байна):**

- Ерөнхий төлөвлөгөөнд бодитоор ямар семантик ангиллууд байдаг, тэдгээрийг юугаар нь таньдаг вэ
- Тэдгээрийг hatch биш, **ангилалтай полигон** болгож гаргах боломж
- Одоогийн `.erks-citygen-site.json` sidecar-ыг өргөтгөх нь зөв зам эсэх
  (санал: `planFeatures.areas[] { id, category, name, polygon }`)
- Схемийн хувилбарын зохицуулалт — Studio одоо v1-ийг яг таг шаарддаг

**PFA (асуулт илгээсэн, хариу хүлээгдэж байна):**

- Портфолио хуудасны `scaleText` найдвартай эсэх, эсвэл зурагдсан мужийн бодит
  хэмжээг метрээр илгээх боломж — масштабын шугам үүнээс хамаарна
- Хуудасны хойд зүгийн эргэлт — хойд сум автомат болох эсэх

**Хэрэглэгчээс:** гарчгийн бэлэн загварууд ямар хэлбэрээр байгаа (§3.2).

## 7. Дараагийн алхам

1. Хэрэглэгч чиглэлийг батлах
2. Гарчгийн загварын хэлбэрийг тодруулах
3. CGA/PFA-гийн хариугаар §3.3 ба 2–3-р шатыг нарийвчлах
4. 1-р шатны дэлгэрэнгүй дизайн — самбарын модель ба шилжилтийн зам
