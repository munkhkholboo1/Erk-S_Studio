# Эх үүсвэрийн илгээлт төсөлд хэрхэн ордог вэ

- Огноо: 2026-09-03
- Шалтгаан: хэрэглэгчийн асуулт — «студио хаалттай, төсөл хаалттай үед эх
  үүсвэрийг студио руу илгээхэд яаж төсөлд өөрчлөлт нь шууд ороод байгаа
  вэ?… бас ямар үед ажиллахгүй вэ»
- Бүх мэдэгдэл **кодоос уншсан**, таамаг биш.

## 1. Яагаад «шууд ороод байгаа» юм шиг санагддаг вэ

**Учир нь илгээлт нь төслийн хавтас дотор бууж байгаа.**

Эх үүсвэр бүр «хүлээн авах хавтас»-тай, ба тэр хавтас нь **төслийн
дотор** байрладаг:

```
Documents\Erk-S Platform\Studio Projects\<төсөл>\
    sources\<эх үүсвэрийн нэр>\deliveries\<огноо-дугаар>\
        001-ЕТ-00 ….pdf
        ….erks-sheets.json          ← манифест
```

AutoCAD/Revit-ээс экспортлоход тэр програм **шууд энэ хавтас руу
бичдэг**. Studio ажиллаж байх шаардлагагүй, төсөл нээлттэй байх ч
шаардлагагүй — файл нь тэр агшинд **аль хэдийн төслийн дотор** байна.

Тиймээс «төсөлд орсон» гэдэг нь **хоёр өөр зүйл**:

| | Хэзээ болдог |
| --- | --- |
| **Файл төслийн хавтаст буух** | экспорт дуусах агшинд, Studio-гүйгээр |
| **Хуудас төслийн бүртгэлд нэгдэх** | Studio уншиж авах агшинд |

Хоёр дахь нь л альбомд, хуудасны жагсаалтад харагдана.

## 2. Studio хэзээ уншиж авдаг вэ

**Хоёр зам, гурав дахь нь байхгүй.**

**(а) Төсөл нээлттэй байхад — секундын дотор.** Studio нээлттэй төслийн
эх үүсвэр бүрийн хүлээн авах хавтсанд **ажиглагч** тавьдаг. Манифест
файл үүсэх/өөрчлөгдөх/нэр солигдох бүрд тэр багцыг **тэр дор нь** уншиж
авна. Дэд хавтас ч ажиглагддаг.

Энэ нь «шууд орлоо» гэж харагддаг хоёр дахь шалтгаан: төсөл нээлттэй
байсан бол үнэхээр шууд орсон.

**(б) Төсөл хаалттай байсан бол — дараагийн нээлтэд.** Төслөө нээх, эсвэл
«Эх үүсвэрээс шинэчлэх» дарахад бүх хүлээн авах хавтас **дахин
шүүрдэгддэг** ба хүлээгдэж байсан бүх багц орж ирнэ.

**Ажиглагч нь зөвхөн нээлттэй төслийнх.** Өөр төслийн илгээлт өөрийнх нь
нээгдэх хүртэл хүлээнэ — алдагдахгүй, хүлээнэ.

## 3. Ямар үед АЖИЛЛАХГҮЙ вэ

Кодын салаа бүрээс:

| # | Нөхцөл | Юу болох |
| --- | --- | --- |
| 1 | **Манифестгүй PDF** | Ажиглагч зөвхөн `*.erks-sheets.json`-ыг хардаг. Ганц PDF хэзээ ч анзаарагдахгүй |
| 2 | **Хүлээн авах хавтаснаас гадуур** бичсэн | Тэр хавтас ажиглагддаггүй — огт харагдахгүй |
| 3 | **Манифест дахь төслийн дугаар зөрсөн** | Татгалзана: «энэ багц өөр төслийнх» |
| 4 | **Төслийн дугаар байхгүй** (шинэ схем) | Татгалзана: «төслийн дугаар дутуу» |
| 5 | **Эх үүсвэрийн дугаар зөрсөн** | Татгалзана: тэр эх үүсвэрийнх биш |
| 6 | **Эх үүсвэр өөр данс/төхөөрөмжид уягдсан** | Тэр эх үүсвэр «энэ машины» биш тул шүүрдэгдэхгүй |
| 7 | **Багц эвдэрхий/уншигдахгүй** | Алдаа мэдэгдэнэ, тэр багц орохгүй |
| 8 | **Синк явж байх үед** | Ажиглагч түр зогсоно, дараа нь орно — алдагдахгүй |
| 9 | **Төсөл хаагдсаны дараа** | Ажиглагч зогсоно — §2(б)-ээр дараагийн нээлтэд орно |

**1 ба 2 нь хамгийн түгээмэл**: экспортын зам буруу заагдсан бол файл
хаа нэгтээ бууж, Studio түүнийг **хэзээ ч** олохгүй.

## 4. Уналт нь чимээгүй юу

**Ихэнхдээ үгүй** — сүүлийн хувилбаруудад тусгайлан хаагдсан:

- **Татгалзсан багц** (3, 4, 5) — шалтгаан нь нэрлэгдэж, тусад нь
  бүртгэгдэнэ
- **Эвдэрхий багц** (7) — алдааны мэдэгдэл гарна
- **Хүлээгдэж буй багц** (төсөл хаалттай байсан) — эх үүсвэр дээр
  «N шинэ багц хүлээгдэж байна (сүүлийнх огноо)» гэж харагдана, ба
  «Эх үүсвэрээс шинэчлэх» дарахыг зөвлөнө

**Чимээгүй үлддэг хоёр нөхцөл:**

**1 ба 2 — файл огт олдохгүй.** Манифестгүй PDF, эсвэл буруу хавтас руу
бичсэн файлын хувьд Studio **тэр файлын оршин байгааг мэдэхгүй**, тиймээс
юу ч хэлж чадахгүй. Талбар хоосон харагдана, ба гаднаас нь «экспорт
бүтэлгүйтсэн» ба «экспорт өөр газар очсон» хоёр **ялгагдахгүй**.

Энэ бол [[partial-results-are-silent]] ангилал: **байхгүй зүйлийн тухай
мэдээлэх боломжгүй.** Мэдээлэх ганц зам нь илгээгч тал — PFA/PFR/CGA
хаана бичсэнээ хэлэх.

**Хуучин хэлбэрийн хүлээн авах хавтас** — тэнд эх үүсвэрийн дугаарын
шалгалт (5) **хийгддэггүй**. Санаатай (хуучин түлхүүрийн нийцэл), гэхдээ
тэр хавтсанд буруу эх үүсвэрийн багц орвол **татгалзахгүй**.

## 5. Товч хариу

> **Зарчим**: экспорт нь төслийн **дотор** бичдэг тул файл шууд «төсөлд»
> ордог. Хуудас болж **харагдах** нь Studio уншиж авахад — төсөл нээлттэй
> бол секундын дотор, хаалттай бол дараагийн нээлтэд.
>
> **Ажиллахгүй үе**: манифестгүй, буруу хавтсанд, өөр төслийн/эх
> үүсвэрийн, өөр төхөөрөмжид уягдсан, эвдэрхий.
>
> **Чимээгүй ганц тохиолдол**: файл огт олдоогүй үе — учир нь Studio
> түүнийг харж ч чадаагүй.
