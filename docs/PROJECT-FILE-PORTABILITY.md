# Төслийн файл — зөөвөрлөлт, хуулбар, форматлалт

- Огноо: 2026-09-03
- Шалтгаан: хэрэглэгчийн асуултууд — «`project.erksproject` үнэхээр ийм
  өргөтгөлтэй файл бид үүсгэж байгаа юу?… Төслийг бүхэлд нь өөр
  төхөөрөмж рүү хуулж ажиллуулж чадах уу? Төхөөрөмжийг форматлах, reset
  хийх. хард эд анги солиход юу болох вэ?»
- Бүх мэдэгдэл **кодоос уншсан ба тестээр хэмжсэн**.

## 1. Тийм — тэр файл бодитоор байдаг

```
ProjectWorkspace.cs:12-13
public const string FileExtension  = ".erksproject";
public const string DefaultFileName = "project.erksproject";
```

Төсөл бүрийн хавтасны үндэст **нэг JSON файл**. Одоогийн хэлбэрийн
хувилбар нь **3**.

### Юу агуулдаг вэ

| Хэсэг | Агуулга |
| --- | --- |
| `projectId` | төслийн дугаар (локал үүсгэгддэг GUID) |
| `identity` | нэр, код, төрөл |
| `foundation` | захиалагч, төлөөлөгч, байгууллагууд |
| `stages` | шатуудын гинж, томилолтууд |
| `sources[]` | бүртгэгдсэн эх үүсвэрүүд (DWG/RVT-ийн **холбоос**) |
| `buildingGroups[]` | барилгын багцууд |
| `cloud` | серверийн холбоос (байвал) |
| `siteContext` | талбайн контекст, зургууд |

**Чухал:** DWG/RVT файлууд **төсөл дотор ордоггүй**. Төсөл нь тэдгээрийн
**зам** ба тэднээс ирсэн **PDF-үүдийг** хадгална.

## 3. Бүхэл төслийг өөр төхөөрөмж рүү хуулбал

**Хэмжсэн тест:**
`ProjectCanonicalCrossDeviceAcceptanceTests.CopyingAWholeProjectToAnotherMachineBringsTheInboxWithIt`

### 3.1 Ажиллах зүйлс

| Юу | Яагаад |
| --- | --- |
| Төсөл нээгдэнэ | JSON нь машинаас хамааралгүй |
| Бүх мэдээлэл (нэр, захиалагч, шатууд) | зам агуулаагүй |
| **Аль хэдийн орсон хуудсууд** | төслийн бүртгэлд суусан, дахин уншихгүй |
| Альбомууд | төслийн дотор, харьцангуй замаар |

> Өмнө нь орсон ажил **бүрэн зөөгдөнө** — нэг үл хамаарах зүйлтэй: **батлагдсан
> даалгаврын (ATD) хуудсууд** хуулбар дээр альбомоос гарна, учир нь тэдний эх
> файлын холбоос шинэ машинд тасарч, ATD-д зориудаар хатуу бодлого үйлчилдэг
> (`PROJECT-FOLDER-CONTAINMENT.md` §2.2). Зургийн рендер ийм биш — үлдэнэ.

### 3.2 🔴 Эвдрэх зүйлс — хоёулаа зам дээр тогтдог

**(1) Хүлээн авах хавтас (`inboxFolder`) — ✅ ЗАСАГДСАН (`0.001.57-dev`, нийтлэгдээгүй).**

Доорх тайлбар нь **засварын өмнөх** зан төлөв. Одоо төсөл нээгдэхэд
хавтас нь төслийн дотор **дахин байрлуулагдаж, файлд хадгалагдана**
(`ProjectWorkspaceStore.RelocateSourceInboxesInsideProject`). Хуучин зам
нь `legacyExternalInbox` талбарт хадгалагдаж **алдагдахгүй**.

Хадгалалт нь заавал: илгээгч плагинууд **ижил файлаас** хаана бичихээ
уншдаг тул зөвхөн санах ойд засвал Studio нэг хавтаснаас хайж, AutoCAD
нөгөө рүү бичих **«хоёр үнэн»** үүснэ.

<details><summary>Засварын өмнө юу болдог байсан бэ</summary>

Хэмжсэн: хуулбарласан төсөл нээхэд `inboxFolder` нь **анхны машины
бүтэн замаа хадгална**. Нээх үед дахин тооцоологддоггүй — ийм дахин
байрлуулалт зөвхөн **хуучин (1-р хэлбэр) шилжилтэд** байдаг
(`ProjectWorkspaceStore.cs:1216`, өмнө :1083).

Үр дагавар:

```
Хуулбар:  D:\Төслүүд\ATD-001\sources\autocad\deliveries\  ← PDF-үүд ЭНД
Ажиглагч: C:\Users\alice\…\ATD-001\sources\autocad\deliveries\  ← ЭНДЭЭС хайна
```

Ажиглагч байхгүй хавтсыг **өөрөө үүсгэдэг**
(`SheetIntakeService.cs:138`) тул алдаа гарахгүй. Studio хоосон хавтас
хараад **чимээгүй хүлээнэ**, ба хуулбартай хамт ирсэн шинэ илгээлтүүд
**хэзээ ч уншигдахгүй**.

> Энэ бол `SOURCE-DELIVERY-INTAKE.md` §3-ын **2-р нөхцөл** (ажиглагдаагүй
> хавтас), гэхдээ буруу экспортоор биш, **хуулбарлалтаар** хүрсэн нь.
> Чимээгүй байдлын шалтгаан ижил: **байхгүй зүйлийн тухай мэдээлэх
> боломжгүй.**

</details>

**Хязгаарлалт:** дахин байрлуулалт нь **Studio төслийг нээх үед**
хийгддэг. Хуулбарласан төслийг Studio-гоор нэг ч удаа нээхээс өмнө
плагин рүү экспортловол хуучин зам хэвээр байна.

**(2) Эх файлын зам (`nativeDocumentPath`) — МЭДЭГДЭЖ эвдэрнэ, нэг тохиолдолд өөрөө засагдана.**

Нээхэд DWG/RVT нь төслийн фолдер дотор **яг нэг** нэрээр олдвол дахин
холбогдоно (`ac6acda`); олдохгүй бол доорх хэвээр.

DWG/RVT-ийн бүтэн зам хадгалагддаг. Өөр машинд тэр зам байхгүй тул эх
үүсвэр **«холбогдоогүй»** төлөвт харагдана. Энэ нь **харагдана** —
чимээгүй биш.

### 3.3 Данс/төхөөрөмжийн уялдаа

`cloud.ownerEmail` эх үүсвэр бүрт хадгалагддаг
(`ProjectCloudSyncMetadata.cs:53`). Өөр дансаар нэвтэрсэн машинд тэр эх
үүсвэр **«энэ машины биш»** тул шүүрдэгдэхгүй — санаатай хамгаалалт
(өөр хүний толийг булаахгүйн тулд).

## 4. Форматлах, reset, эд анги солих

### 4.1 Юу сэргэх вэ

| Юу | Сэргэх үү |
| --- | --- |
| Төслийн үндсэн мэдээлэл (сервертэй холбоотой бол) | ✅ серверээс |
| **Нийтэлсэн** альбомын хувилбарууд | ✅ татагдана, хэшээр шалгагдана |
| Түншийн лого, эх үүсвэрийн зургууд | ✅ |
| Эх үүсвэрийн бүртгэл (нэр, түлхүүр, хэш) | ✅ метадата |

### 4.2 Юу сэргэхгүй вэ

| Юу | Яагаад |
| --- | --- |
| **Ирсэн PDF илгээлтүүд** | серверт **метадата/хэшээр** бүртгэгддэг; буцааж татах зам олдсонгүй |
| DWG/RVT эх файлууд | төсөлд хэзээ ч байгаагүй — тэдгээр нь эх машин дээр |
| Сервертэй холбогдоогүй төслүүд | огт байршаагүй |
| Нийтлээгүй альбомын ноорог | локал |

> **Хамгийн чухал өгүүлбэр:** сервертэй холбогдоогүй төсөл нь **зөвхөн
> тэр дискэн дээр** байдаг. Форматлах нь түүнийг эцэслэн устгана.

### 4.3 Хатуу диск солих

Дискний солилт нь **форматлахтай ижил** — локал файлууд алга болно.
Нэмэлт нэг зүйл: **төхөөрөмжийн хурууны хээ өөрчлөгдөж мэднэ**, тэгвэл
эх үүсвэрийн уялдаа тасарч дахин холбох шаардлагатай болно.

### 4.4 Тиймээс — зөвлөмж

1. **Хавтсыг бүхэлд нь хуулах нь ажиллана** (§3-ын хязгаарлалттай)
2. Чухал ажлыг **сервер рүү нийтлэх** — тэр нь буцаж татагддаг ганц зам
3. Дискийг солихоос өмнө **төслийн хавтсуудыг хуулах**

## 5. Нэрлэгдсэн чимээгүй салаа — хаагдав

Энэ баримт нэг чимээгүй эвдрэл олов: **хуулбарласан төслийн хүлээн авах
хавтас**. Алдаа гарахгүй, тэмдэглэл гарахгүй, хоосон хавтас үүснэ, ба
хэрэглэгч «яагаад шинэ хуудас орж ирэхгүй байна» гэж гайхна.

**Хаагдсан** (`0.001.57-dev`, нийтлэгдээгүй): §3.2(1)-ийг үзнэ үү. Хэвийн төсөлд (хавтас аль
хэдийн дотор) юу ч өөрчлөгдөхгүй — хоёр чиглэлд тесттэй, ба засварыг
зориудаар эвдэж тест улаан болохыг **баталсан**.

Бусад бүх эвдрэл (эх файлын зам, өөр данс, сервергүй төсөл) нь **ил
харагддаг** буюу хэрэглэгч мэднэ.
