- Огноо: 2026-09-03

  хэрэгтэй… тухайн төхөөрөмжийн төсөлд гүйцэтгэж буй бүх үүргийг
  агуулсан zip файл… тэндээсээ студиогоос backup үйлдэл хийснээр…
  студио өмнөх төхөөрөмжийн үүргийг залгамжилж авах ёстой»
- Урьдчилсан нөхцөл: `PROJECT-FOLDER-CONTAINMENT.md` (багцын агуулгын
  спек), `PROJECT-FILE-PORTABILITY.md` (одоогийн зан төлөв)

## 1. UI нэршил ба байршил

| Үйлдэл | Байршил | Нэр |
| --- | --- | --- |
| Багц үүсгэх | Төсөл → цэс | **«Багцлах…»** |
| Багцаас сэргээх | Эхлэлийн дэлгэц + Файл цэс | **«Багцаас сэргээх…»** |

Файлын өргөтгөл: **`.erkspack`** (zip). «Backup» гэсэн үг **хэрэглэхгүй**
— энэ нь нөөц биш, **үүргийн шилжүүлэг**. Нөөц гэж нэрлэвэл хэрэглэгч
хоёр машин зэрэг ажиллана гэж ойлгоно.

## 2. Багцын агуулга — аудит нь спек

`PROJECT-FOLDER-CONTAINMENT.md`-ийн гурван багана шууд буулгагдана.

### 2.1 Орно ✅

- **Төслийн фолдер бүхэлдээ** — §2(а)-гийн долоон талбар аль хэдийн
  фолдер дотор
- **Багцын manifest** (§3)

### 2.2 ОРОХГҮЙ — зориудаар 🔵

| Юу | Яагаад |
| --- | --- |
| DWG/RVT эх файлууд | загварын шийдвэр; тэдгээр нь эх машины ажлын файл |
| Итгэмжлэл | CredMan дотор, **фолдерт байхгүй** |
| Ботын токен/ПИН | §5 |

### 2.3 ⚠️ «Гадна-санамсаргүй» — ЗӨӨХГҮЙ, ЗАСНА

Энэ л сонирхолтой багана байсан. Хэмжсэн дүгнэлт:

> Тэдгээрийн **ачаалал аль хэдийн фолдер дотор байна**
> (`relativePath`). Гадна үлдсэн нь зөвхөн **хуучин холбоосын зам**.

Тиймээс багц тэр гадны файлуудыг **зөөх шаардлагагүй** — зөөсөн ч
шинэ машинд өөр замд буух тул холбоос сэргэхгүй.

**Зөв шийдэл:** багц үүсгэхэд тасрах холбоосуудыг **ил тэмдэглэнэ**,
дараа нь сэргээхэд тэдгээр нь «холбоос тасарсан» төлөвт орно —
**зам нь хуурамчаар үлдэхгүй**.

| Талбар | Багцлахад |
| --- | --- |
| `visualizations[].linkedSourcePath` | manifest-д бичигдэж, талбар **цэвэрлэгдэнэ** |
| `documents[].linkedSourcePath` | мөн адил |
| `cloud.lastReceivedAlbumPdfPath` | цэвэрлэгдэнэ — `sha256` байгаа тул дахин татагдана |
| `migration.sourcePath` | үлдэнэ (түүхэн бичлэг, ашиглагддаггүй) |
| `localBindingAccountEmail` / `…DeviceFingerprint` | **цэвэрлэгдэнэ** — өөр төхөөрөмжийн хуучирсан уялдаа |

> 🔴 **Энэ нь `PROJECT-FOLDER-CONTAINMENT.md` §2.1-ийн согогийг
> дайрна.** Тэр согог засагдаагүй бол `linkedSourcePath` цэвэрлэх нь
> зургийг **боломжтой болгож** алдаа санамсаргүй засна; засагдвал энэ
> нь зөв, санаатай зан төлөв болно. **Дараалал: §2.1 эхэлнэ.**

## 3. Багцын manifest

```
erkspack.json
  formatVersion
  projectId              төслийн дугаар (хоёр хуулбарт ижил)
  instanceId             ← ШИНЭ, §4
  packagedAtUtc
  packagedFromDevice     хүний унших нэр (машины нэр)
  packagedByAccount      имэйл
  contents               файлын тоо, нийт хэмжээ
  brokenLinks[]          §2.3-аар цэвэрлэгдсэн замууд
  succession             §4
```

`packagedFromDevice` нь **хурууны хээ биш** — хүн уншиж «энэ багц миний
хуучин зөөврөөс» гэж таних зорилготой. Хурууны хээ нь identity, багцын
шошго биш.

## 4. 🔴 Залгамжлал — хэмжигдсэн дутагдал

### 4.1 Төсөл өөрийгөө таньдаггүй

Хэмжив: `ProjectWorkspace`-д **төхөөрөмж/хуулбарын тэмдэг байхгүй**.
`DeviceFingerprint` нь зөвхөн **хөрөнгийн нэхэмжлэлд** байдаг
(`ProjectWorkspace.cs:296`), төсөлд өөрт нь биш.

> Хоёр хуулбар **ялгагдахгүй**: ижил `projectId`, тэмдэг байхгүй.
> «Аль нь канон бэ» гэдгийг илэрхийлэх **талбар байхгүй**.

Тиймээс залгамжлалд **`instanceId` шинээр хэрэгтэй** — төслийн дугаараас
тусдаа, хуулбар бүрт өөр. Сэргээх үед **шинэ `instanceId` олгогдоно**,
ба өмнөхийг `succession.previousInstanceId`-д бичнэ.

Энэ нь [[store-facts-not-conclusions]]: «канон эсэх» гэдэг **дүгнэлт**
хадгалагдахгүй, **аль хуулбар болох** нь хадгалагдана. Канон эсэхийг
бүртгэл шийднэ.

### 4.2 ⚠️ Сервергүй төсөлд залгамжлалыг ХҮЧЛЭХ БОЛОМЖГҮЙ

Хуучин машин дээрх хуулбар нь дискэн дээрээ бүрэн ажиллагаатай хэвээр.
Түүнийг зогсоох ганц зам нь **түүнд хэлэх**, ба хэлэх суваг нь сервер.

| Төслийн төрөл | Хуучин хуулбар мэдэх үү |
| --- | --- |
| Сервертэй холбоотой | **тийм** — дараагийн холболтдоо |
| **Зөвхөн локал** | **үгүй — хэзээ ч** |

> Багц нь хоёр-амьд-хуулбарын асуудлыг **сервертэй төсөлд** шийднэ.
> Локал-зөвхөн төсөлд энэ нь **зохион байгуулалтын дүрэм**, техникийн
> хаалт биш.

Үүнийг ил бичсэн шалтгаан: багц үйлдэл нь «шилжүүлэг» гэж нэрлэгдэх тул
хэрэглэгч **хуучин нь унтарсан** гэж ойлгоно. Локал төсөлд тэр нь үнэн
биш, ба [[your-own-writing-is-unchecked]] ангиллаар дараа уншигч үүнийг
хаалт гэж уншина.

**UI-д:** локал-зөвхөн төслийг багцлахад анхааруулна —
«Энэ төсөл сервертэй холбогдоогүй тул хуучин төхөөрөмж дээрх хуулбар
өөрөө зогсохгүй. Шилжүүлсний дараа тэндээс нь устгана уу.»

### 4.3 SRV-тэй тохирох гэрээ

| Талбар | Хэн |
| --- | --- |
| `instanceId` олгох/бичих | STU (локал) |
| Залгамжлалын бүртгэл, «аль нь канон» | SRV |
| Хуучин машинд мэдэгдэх мессеж | SRV буцаана, STU харуулна |

Хуучин машинд харагдах текст: **«Энэ төслийн үүрэг [шинэ төхөөрөмж]-д
шилжсэн ([огноо]).»** Төхөөрөмжийн нэр нь manifest-ийн
`packagedFromDevice`-тэй ижил эх сурвалжтай байх ёстой, эс бөгөөс
хэрэглэгч хоёр өөр нэр хараад аль машин болохыг таана.

## 5. Бот-төлөв багцаар ЗӨӨГДӨХГҮЙ

Мастерын заалт, ба **бүтцээр ч тийм**:

| Юу | Хаана байдаг |
| --- | --- |
| Ботын итгэмжлэл | **CredMan**, `server\|email` хэшээр түлхүүрлэгдсэн |
| Төхөөрөмжийн уялдаа | хурууны хээ |
| ПИН-ээр тайлагддаг blob | CredMan |

**Гурвуулаа төслийн фолдорт байхгүй.** Тиймээс «zip-д оруулахгүй» гэдэг
нь бодлогын сонголт төдийгүй — оруулах зүйл **байхгүй**.

Шинэ машинд бот **дахин bootstrap** хийгдэнэ (RFC-003 §2-ын урсгал):
эзэмшигч лиценз эрхээр нэвтэрч, суудал үүсгэж, ПИН тавина. Багц нь
төслийг авчирна, **суудлыг биш**.

> Багц нь бот-суудлын шилжүүлгийг **орлохгүй, дагалдана**.
