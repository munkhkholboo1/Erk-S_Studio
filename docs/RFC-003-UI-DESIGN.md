# RFC-003 UI дизайн — бот, гишүүн, identity

- Огноо: 2026-09-03
- Хамрах хүрээ: бот үүсгэх, гишүүн холбох, ботын удирдлага (ПИН),
  төлөвөөс гарах, identity-солилт
- Гэрээ: `Erk-S-Server/docs/contracts/bot-link-invitation.example.json`,
  `bot-state-studio-session.example.json`, `bot-token-and-pin.example.json`
- Загвар: `RFC-003-ORGANIZATION-BOT-MEMBERS.md` §21, §28, §31, §36

## 0. Хоёр зарчим, нэг үндэс

**(1) Интерфейс үнэн ярина.** Саарал товч «чи эрхгүй» гэж хэлдэг. Хэрэв
хэрэглэгч эрхтэй мөртлөө нөхцөл дутуу бол товч **идэвхтэй байж, дарахад
шалтгааныг нэрлэнэ**. §28-ын эзэмшигчийн дүрэм нь үүний нэг илрэл.

**(2) Клиент таамаглахгүй.** UI-гийн шалгалт нь дэмий round-trip хэмнэх
**эелдэг байдал**, шийдвэр биш. Серверийн татгалзал ирвэл түүнийг
харуулна. Хугацаа, эрх, суудлын байдал — бүгд серверийнх.

> Хоёулаа нэг үндэстэй: **шийдвэрийг мэдээлэл байгаа давхаргад.**
> Клиент таамаглаж хаавал хууль ёсны хэрэглэгчийг хаана.

Байгаа `StudioNotificationsDialog` энэ загварыг **аль хэдийн барьдаг**:
дуусах огноог багана болгон харуулдаг ч товчийг түүгээр хаадаггүй
(`CollaborationDialogs.cs:355, 389`). Шинэ дэлгэцүүд үүнийг дагана.

## 1. Identity-солилтын цэс

Шеллийн баруун дээд буланд. **Төлөв бүрийг тодоор нэрлэнэ** — хэн, аль
байгууллага, ямар горим (§31.1-ийн найман төлөв).

```
┌─ Одоогийн байдал ──────────────────────────┐
│  ●  Мөнхболд · «Эрк-Эс» ХХК · ЭЗЭМШИГЧ     │
│     лиценз баталгаажсан                     │
├────────────────────────────────────────────┤
│  Өөр байдлаар нэвтрэх…                     │
│  Гарах                                      │
└────────────────────────────────────────────┘
```

Мөрийн бүтэц: **нэр · байгууллага · горим**. Гурвуулаа үргэлж байна —
хоосон орхивол хэрэглэгч аль эрхээр ажиллаж байгаагаа таана.

| Төлөв | Мөр |
| --- | --- |
| Хувийн, лицензгүй | `Мөнхболд · хувийн · лицензгүй` |
| Хувийн, лицензтэй | `Мөнхболд · хувийн · лицензтэй` |
| Гишүүн | `Мөнхболд · «Эрк-Эс» ХХК · гишүүн` |
| Эзэмшигч | `Мөнхболд · «Эрк-Эс» ХХК · ЭЗЭМШИГЧ` |
| Бот | `«Эрк-Эс» ХХК · БОТ: Зураг-1 · төхөөрөмжийн суудал` |

Бот мөрөнд **хүний нэр байхгүй** — суудал нь хүнийх биш. §21.2-ын
«эрх нь session-ынх» ялгааны шууд илэрхийлэл.

## 2. «Бот болгох» — зөвхөн эзэмшигчийн session

**Байрлал:** Тохиргоо → Байгууллага → Төхөөрөмжүүд.

**Харагдах нөхцөл:** лиценз баталгаажсан эзэмшигчийн session (§31.1-ийн
5-р төлөв). Бусад бүх төлөвт **байхгүй** — саарал биш, байхгүй.

> Энэ бол §31.3-ын ялгаа: UI нуух нь **зөв замыг үзүүлэх**, хаалт биш.
> Жинхэнэ хаалт нь серверийн татгалзал. UI үүнийг давхарладаг.

### 2.1 Урсгал

```
[ Энэ төхөөрөмжийг бот болгох ]
        ↓
┌─ Бот үүсгэх ───────────────────────────────────────┐
│  Нэр      [ Зураг-1                            ]   │
│  ПИН      [ 4 орон ]   ← зөвхөн 4 тоо              │
│                                                     │
│  ⚠ Энэ төхөөрөмж бот болмогц:                      │
│     • таны нэвтрэлт энэ машинаас УСТАНА             │
│     • буцаах ганц зам нь дахин нэвтрэх              │
│     • энэ машины төслүүд ботод шилжинэ              │
│                                                     │
│              [ Болих ]  [ Бот болгох ]              │
└────────────────────────────────────────────────────┘
```

**ПИН талбарт хүч хэмжигч, анхааруулга, блоклолт БАЙХГҮЙ.** `0000` ба
`1234` зөвшөөрөгдөнө (§36.2 — зарлиг, орхигдол биш). Ганц шалгалт нь
**яг 4 тоо**.

### 2.2 Итгэмжлэл устгах нь буцаах цэг

§36.1: устгаж чадаагүйг **орж чадаагүйд** тооцно.

```
Бот болгож байна…
  1. Сервер: суудал үүсгэх          ✓
  2. Энэ машин: нэвтрэлт устгах     ✗  ← энд зогсоно
  3. Бот төлөвт шилжих              — хийгдэхгүй
```

Хоёр дахь алхам бүтэлгүйтвэл:

> **«Бот болгож чадсангүй.** Энэ машины нэвтрэлтийг устгаж чадаагүй тул
> шилжилтийг зогсоов — хагас шилжсэн төхөөрөмж үлдээхгүйн тулд. Studio-г
> дахин нээгээд оролдоно уу.»

Хэсэгчилсэн шилжилт хийвэл «бот болгох» нь ажилтны эргүүлж болох
**унтраалга** болно.

**Хэрэгжих боломжтой — хэмжигдсэн.** `ICredentialStore.Delete` нь `void`
буцаадаг ч тэр нь үр дүнг хаядаг гэсэн үг **биш**:

```
StudioAccountService.cs:2784
if (!CredDelete(...) && Marshal.GetLastWin32Error() != ErrorNotFound)
    throw new Win32Exception(...);
```

Бүтэлгүйтэл нь **алдаа шидэлтээр** дамждаг, ба `StudioSessionEpochGate.Commit`
(`:55`) түүнийг **залгидаггүй**. Тиймээс «устгаж чадаагүй = орж чадаагүй»
дүрэм нь `try/catch`-гүйгээр аяндаа биелнэ.

`ErrorNotFound` тэвчигддэг нь зөв: устгах итгэмжлэл байхгүй бол
«энэ машинд эзэмшигчийн итгэмжлэл байхгүй» гэсэн эцсийн нөхцөл аль хэдийн
хангагдсан.

⚠️ **Гэхдээ энэ зам `SignOut()`-ыг ДАХИН АШИГЛАХГҮЙ.** Тэр нь метадата
устгахдаа `IOException`-ыг **залгидаг** (`:1716`) тул «итгэмжлэл алга,
метадата байгаа» гэсэн хагас төлөв чимээгүй үүсэх боломжтой. Бот-төлөвт
орох зам өөрийн шалгалттай байна.

## 3. Гишүүн холбох (урилга)

Байгаа `ProjectMemberInvitationDialog`-ийн хэлбэрийг дагана.

### 3.1 «Шууд нэмэх» БАЙХГҮЙ

Эзэмшигч хүний өмнөөс зөвшөөрч чадахгүй (`invitation_not_yours`).
Холболт **хоёр талт** — эзэмшигч урина, хүн зөвшөөрнө.

> Ноорогт байсан «энэ хүнийг шууд нэмэх» товчийг **хасна**. Тэр зам
> байхгүй; байвал хоёр дахь тал хэлбэр төдий болж, **хүний нэр
> зөвшөөрөлгүйгээр** булангийн хүснэгтэд гарна.

### 3.2 Хоёр өөр амжилтын мессеж

Сервер `openedNewInterval`-аар **юу болсныг** хэлнэ:

| `openedNewInterval` | Мессеж |
| --- | --- |
| `true` | «**Батбаяр** багт нэгдлээ.» |
| `false` | «**Батбаяр**-т «Ногоон Гудамж» төсөл нэмэгдлээ.» |

Хоёуланг «урилга зөвшөөрөгдлөө» гэвэл эзэмшигч **шинэ хүн нэгдсэн** гэж
андуурч ажлын хоногийг давхар тооцно.

### 3.3 Суудал эзэлсэн бол — «эхлээд салга»

`invitation_seat_linked_to_another_person`:

> «Энэ суудалд **Батбаяр** холбогдсон байна. Өөр хүн холбохын өмнө
> түүнийг салгах хэрэгтэй.»
> `[ Болих ]  [ Батбаярыг салгах… ]`

Чимээгүй сольж болохгүй: тэр нь **карьерын түүхийг дахин бичих** буюу
буцаагдахгүй.

### 3.4 Хугацаа — харуулна, хаахгүй

`Sent` төлөв нь «зөвшөөрч болно» гэсэн үг **биш** — хугацаа
`expiresAtUtc`-аас **тооцоологддог**.

Гэхдээ UI тэр тооцоог давтахдаа **клиентийн цаг**-аас хамаарна:

| Клиентийн цаг | UI өөрөө шийдвэл |
| --- | --- |
| хоцорсон | дууссаныг хүчинтэй гэж үзүүлнэ |
| **түрүүлсэн** | **хүчинтэйг хаана** ← ноцтой |

Тиймээс: дуусах огноог **харуулна**, товчийг **саарал болгохгүй**.
Дарахад `invitation_expired` ирвэл түүнийг харуулна.

## 4. Ботын удирдлага

**Байрлал:** Тохиргоо → Байгууллага → Төхөөрөмжүүд → [суудал].
Зөвхөн эзэмшигчийн session.

```
┌─ Зураг-1 ──────────────────────────────────┐
│  Төхөөрөмж   DESKTOP-4F2A                  │
│  Холбогдсон  Батбаяр                       │
│  ПИН         ••••   [ Харах ]              │
│  Сүүлд идэвхтэй  2026-09-03 14:22          │
│                                             │
│  [ Салгах ]  [ ПИН солих ]  [ Чөлөөлөх ]   │
└────────────────────────────────────────────┘
```

### 4.1 ПИН уншилт — хэн уншиж чадах вэ

| Хэн | Уншина уу |
| --- | --- |
| Эзэмшигч | **тийм** — hash биш, буцаан унших |
| Бот өөрөө | **үгүй** — өөрийн түгжээнийхээ түлхүүрийг барих байсан |
| Ажилтан | **үгүй** — тэр оруулдаг, уншдаггүй |

`bot_pin_reveal_is_owners_only`.

### 4.2 Алсаас ПИН солих — хоёр зүйл нэг мессежээр

Сервер солилт ба **дахин бүртгүүлэх шаардлагыг нэг утгаар** буцаана.
UI хоёуланг нэг мессежид:

> «ПИН **7391** болж солигдлоо. Тэр төхөөрөмж дээр **дахин бүртгүүлэх**
> шаардлагатай — шинэ ПИН-ийг дангаар нь оруулахад ажиллахгүй.»

Хоёр дахь өгүүлбэргүй бол ажилтан шинэ ПИН оруулаад ажиллахгүй, ба
шалтгаан нь **хаана ч харагдахгүй**.

### 4.3 Түгжээ — Studio мэдээлнэ

Сервер оролдлого тоолохгүй, хармагүй. Studio `ReportDeviceLockout`
дуудна. Эзэмшигчийн жагсаалтад:

> `⚠ Зураг-1 — ПИН буруу оролдлогоор түгжигдсэн` `[ Тайлах ]`

## 5. Төлөвөөс гарах — хоёр зам, гурав дахь нь алга

| Зам | Хэн | Хэзээ хүчинтэй |
| --- | --- | --- |
| **Алсаас чөлөөлөх** | эзэмшигч хаанаас ч | төхөөрөмж **дараагийн холболтдоо** мэднэ |
| **Төхөөрөмж дээр** | эзэмшигч тэр машин дээр нэвтэрнэ | шууд |

**Бот-төлөв өөрөө өөрийгөө унтраахгүй**
(`bot_state_exit_requires_owner_sign_in`). Орох, гарах **нэг хаалга** —
энэ тэгш хэм нь §2.2-ын итгэмжлэл-устгалыг утгатай болгодог зүйл.

### 5.1 Дараагийн холболтын мессежүүд

| Код | Мессеж |
| --- | --- |
| `bot_state_released_remotely` | «Энэ төхөөрөмжийг **«Эрк-Эс» ХХК** чөлөөлсөн байна.» |
| `bot_state_not_found` | «Энэ төхөөрөмж ботын төлөвт байгаагүй байна.» |
| `bot_state_seat_unavailable` | «Суудал устгагдсан байна.» |
| `bot_state_requires_owner_session` | «Ботын төлөвөөс гарахад эзэмшигч нэвтрэх шаардлагатай.» |

Эхний хоёр нь **тусдаа** байх ёстой: «чөлөөлөгдсөн» ба «байгаагүй» хоёр
өөр түүх. Нэг мессеж өгвөл ажилтан алийг нь болохыг таана.

**Түдгэлзүүлсэн** суудал үргэлжилнэ; зөвхөн **устгал** эцсийнх.

## 6. Татгалзлын текстүүд — бүгд нэрлэгдсэн

| Нөхцөл | Текст |
| --- | --- |
| Өөр байгууллагын бот энэ машинд | «Энэ төхөөрөмж **«Эрк-Эс» ХХК**-ийн суудал болсон байна.» |
| B нь А-гийн ботыг чөлөөлөх гэв | «Энэ суудал **«Эрк-Эс» ХХК**-д харьяалагдана. Зөвхөн тэр байгууллагын эзэмшигч чөлөөлнө.» |
| Лицензгүй эзэмшигч бот үүсгэх гэв | «Бот үүсгэхэд идэвхтэй лиценз шаардлагатай.» |

**Байгууллагын нэр үргэлж орно.** «Аль хэдийн бот байна» гэсэн ерөнхий
алдаа нь олон суудалтай эзэмшигчийг **таах** байдалд оруулна (§30).
