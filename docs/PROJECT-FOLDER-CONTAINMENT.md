# Төслийн фолдер — багтаамжийн аудит ба зам-хамаарлын дизайн

- Огноо: 2026-09-03
- Асуулт (хэрэглэгчийн эх үг): «Гол асуудал бид төслийг фолдертой нь
  хуулах ёстой юу? Фолдертой нь хамт хуулах хангалттай юу? Үнэхээр
  төсөлтэй холбоотой бүх мэдээлэл төслийн фолдерт агуулагдаж чадаж
  байна уу?»
- Бүх мэдэгдэл **кодоос хэмжсэн**.

## 1. Богино хариу

> **Тийм — зургийн хувьд.** 12 зам-талбар хэмжигдэж, олдсон согог
> (§2.1) **засагдав** (0.001.57): хуулбарласан төсөл визуализацаа
> альбомдоо хадгална.
>
> ⚠️ **Баримтууд өөр бодлоготой** — §2.2-ыг үзнэ үү. Хуулбарласан төсөл
> ATD-гийн хуудсуудаа **алсаар хэвээр**, ба энэ нь **зориудын, тесттэй**
> зан төлөв.

Зураг, баримтын **ачаалал** нь агуулгаараа шалгагддаг (SHA-256),
төхөөрөмжөөр биш — тэр хэсэг зөв. Согог нь **өөр код замд** байна.

## 2. Гурван баганат аудит

Төслийн файл дахь **бүх** зам-талбар:

### (а) Фолдер дотор — хуулбартай хамт зөөгдөнө ✅

| Талбар | Хэлбэр |
| --- | --- |
| `primaryAlbum.documentPath` | харьцангуй (`albums/…`) |
| `primaryAlbum.outputFolder` | харьцангуй (`albums`) |
| `primaryAlbum.lastPdfPath` | **харьцангуй болгож** хадгалагддаг (`ToRelativePath`) |
| `documents[].relativePath` | харьцангуй, төслийн дотор тайлагдана |
| `visualizations[].relativePath` | харьцангуй |
| `plans[].relativePath` | харьцангуй |
| `sources[].inboxFolder` | **дахин байрлуулагдана** (0.001.57) |

**Ачааллын шалгалт агуулгаар:** `HasVerifiedPayload` нь **файл байгаа
эсэх + SHA-256** дээр тогтдог
(`StudioAuxiliarySourceLocalityPolicy.cs:311-329`), ба
`ResolvePayloadPath` нь **`relativePath`-ыг эхэлж** үзнэ (`:359`).

> Тиймээс өөр машин, өөр данс, өөр хурууны хээ — **хамаагүй**. Зураг нь
> хэшээрээ таарвал харагдана.

Энэ нь чухал: зурган дээр `localBindingAccountEmail` ба
`localBindingDeviceFingerprint` талбарууд **байдаг** ч ачааллын
шалгалтад **оролцдоггүй**. Уялдаа нь хэн холбосныг тэмдэглэдэг, харах
эрхийг шийддэггүй.

### (б) Гадна — ЗОРИУДААР 🔵

| Юу | Яагаад |
| --- | --- |
| DWG/RVT эх файлууд | загварын шийдвэр: эх нь байрандаа үлдэнэ, төсөл нь **PDF-ийг** авна |
| Данс/итгэмжлэл | Windows Credential Manager, Windows-хэрэглэгч тус бүрд |
| Серверийн канон мэдээлэл | серверт амьдардаг |

Эдгээр нь «дутуу» биш — **төсөлд хамаарахгүй** зүйлс.

### (в) Гадна — САНАМСАРГҮЙГЭЭР ⚠️

Дөрвөн талбар гадны замыг санаж үлддэг. Гурав нь хор хөнөөлгүй, **нэг нь
согог**:

| Талбар | Юу болдог | Ноцтой юу |
| --- | --- | --- |
| `documents[].linkedSourcePath` | эх баримтыг ажиглах холбоос | хоёрдогч |
| `cloud.lastReceivedAlbumPdfPath` | татсан альбомын кэшийн заалт | **үгүй** — хамт `sha256` байдаг тул кэш алдвал дахин татна |
| `migration.sourcePath` | хаанаас шилжсэний түүхэн бичлэг | **үгүй** — ашиглагддаггүй |
| `visualizations[].linkedSourcePath` | эх зургийг ажиглах холбоос | 🔴 **СОГОГ — §2.1** |

## 2.1 🔴 Олдсон согог: хуулбар өөрийн визуализацийг альбомоосоо хаядаг

Гурван кодын хэлхээ:

```
1. ProjectAssetSourceReconciler.cs:277
   inspectionPath = hasLinkedSource ? linkedPath : storedPath;
        ↑ ГАДНЫ замыг ЭХЭЛЖ үзнэ

2. :278-283  файл байхгүй → IsAvailable = false

3. ProjectVisualizationSource.cs:279
   .Where(image => image.IsAvailable && image.IsIncludedInAlbum)
        ↑ альбомоос ХАСАГДАНА
```

Хуулбарласан төсөлд `linkedSourcePath` нь **анхны машины** гадны зургийг
заана. Тэр машин дээр байхгүй тул зураг «боломжгүй» болж, **альбомоос
хасагдана** — хэдийгээр ачаалал нь `relativePath`-аар төслийн дотор
**бүрэн байгаа** ба хэшээрээ шалгагдах боломжтой.

**Хоёр код зам, хоёр өөр хариу:**

| Хаана | Аль замыг эхэлж үзнэ |
| --- | --- |
| `StudioAuxiliarySourceLocalityPolicy:359` | **`relativePath`** — төслийн дотор ✅ |
| `ProjectAssetSourceReconciler:277` | **`linkedSourcePath`** — гадна ❌ |

Энэ нь [[verify-the-shape-you-acted-on]] ангилал: нэг объектын хоёр
дүрслэл зөрж байна.

**✅ ЗАСАГДАВ (0.001.57).** Холбоос тасарсан ч төслийн доторх ачаалал
байвал зураг **боломжтой хэвээр** үлдэж альбомд байна; тасралт нь
`linkedSourceMissing` тугаар тусад нь тэмдэглэгдэж хэрэглэгчид
харагдана («эх файлтай холбоо тасарсан: N»).

Хоёр чиглэлд тесттэй: холбоос сэргэвэл туг арилна; **ачаалал ч алга
болвол** зураг жинхэнээсээ боломжгүй болж альбомоос гарна.

## 2.2 ⚠️ Баримтууд ЗОРИУДААР өөр бодлоготой

Энэ засварыг баримтуудад ч хийж үзэв — **гурван тест унав**. Тэдгээр нь
буруу байсангүй, **надад хэлж байсан**:

> Батлагдсан даалгавар (ATD)-ын эх файл алга болбол **альбомоос гардаг**,
> хэдийгээр төслийн өөрийн хуулбар дискэн дээр үлддэг.

Энэ нь албан ёсны баримтын хувьд өөр асуудал — зургийн рендер биш.
Тиймээс баримтын хэсэг **буцаагдав**: зөвхөн визуализац засагдсан.

**Үр дагавар (нээлттэй):** хуулбарласан төсөл ATD-гийн хуудсуудаа
алсаар хэвээр. Албан ёсны баримт рендер шиг аашлах ёстой юу гэдэг нь
**энэ давхаргаас дээших шийдвэр**, согог биш.

### Хоёр үйл явдал ялгагдаж байгааг тест барина

`LinkedAtdAndVisualizationReconciliation_CreatesScopedRemovalClaims`:

| Юу болов | ATD | Визуализац |
| --- | --- | --- |
| Эх файл устав | альбомоос гарна | **үлдэнэ** |
| Үүлэнд мэдэгдэх | **хасалтын нэхэмжлэл** | нэхэмжлэлгүй |
| Тэмдэг | «олдсонгүй» | «холбоо тасарсан» |

«Эх үүсвэр хасагдсан» ба «холбоос тасарсан» хоёр өөр үйл явдал гэдэг нь
энэ тестээр **батлагдана**.

## 3. Зарлиг: «файл өөрийн байгаа фолдероосоо үнэнээ шүүнэ»

Мастерын зарлиг — дахин байрлуулалт зөвхөн inbox-д биш, **бүх
фолдер-хамааралт линкэд**.

Хэмжсэнээр **ихэнх нь аль хэдийн ийм байна**: §2(а)-гийн долоон
талбараас зургаа нь **харьцангуй**, ба харьцангуй зам нь тодорхойлолтоор
«өөрийн фолдероосоо тайлагддаг». Тиймээс зарлигийн агуулга нь
**хэрэгжсэн**; үлдсэн нь **гурван хоёрдогч талбар** (§2(в)).

### 3.1 Санал: дахин бичихийн оронд харьцангуй хадгалах

Мастерын хоёр дахь санал — «дотоод замуудыг харьцангуйгаар хадгалж
runtime-д тайлах» — нь **илүү зөв суурь**, ба **аль хэдийн ноёрхож
байгаа хэлбэр**. Дахин бичилт нь зөвхөн `inboxFolder`-т хэрэгтэй болсон
нь тэр талбар **үл нийцэж** абсолют байсных.

> **Санал:** `inboxFolder`-ыг ч харьцангуй болгох (`sources/<нэр>/deliveries`).
> Тэгвэл дахин байрлуулалт **огт хэрэггүй** болно.

**Шилжилтийн зам** (өгөгдөл алдагдахгүй):

| Алхам | Юу |
| --- | --- |
| 1 | Унших үед: абсолют бол харьцангуй болгож тайлна (одоогийн дахин байрлуулалт **тэр үүргийг гүйцэтгэнэ**) |
| 2 | Бичих үед: төслийн дотор бол **харьцангуйгаар** бичнэ |
| 3 | Хуучин Studio нээвэл? — **эвдэрнэ** |

⚠️ **3-р мөр нь блоклогч.** `inboxFolder`-ыг харьцангуй болгох нь
**хэлбэрийн хувилбар өсгөх** шаардлагатай, ба **PFA/PFR ижил файлаас
уншдаг** тул гурван бүтээгдэхүүний зэрэгцээ өөрчлөлт болно.

> Тиймээс энэ нь §34-ийн identity-гэрээтэй ижил ангилал: **бодит
> гаралтыг код бичихээс өмнө солилцоно.** Одоогийн дахин байрлуулалт нь
> ажиллаж байгаа тул яаралтай биш.

## 4. Эх үүсвэрийн авто-дахин-холболт (дизайн)

Мастерын зөвлөмж: **тийм**, ийм дүрмээр.

### 4.1 Суурь дүрэм

> **Эх үүсвэрийн identity = `sourceId`. Зам бол шинж чанар, нэр биш.**

Кодод аль хэдийн ийм: `ProjectDesignSource.Id` нь GUID, зам биш
(`ProjectDesignSource.cs:11`). Тиймээс дүрэм нь **шинэ биш, ил
болгогдож байна**.

### 4.2 Хоёр механизм

**(1) Илгээлтээр шинэчлэх.** Ижил `sourceId`-тай бүртгэл/илгээлт **өөр
замаас** ирвэл `nativeDocumentPath` шинэчлэгдэнэ.

**(2) Нээхэд fallback хайлт.** Зам олдохгүй бол төслийн фолдороос
**харьцангуйгаар** хайна (файлын нэрээр).

### 4.3 ⚠️ Дизайны сэрэмжлүүлэг: «сүүлийн бүртгэл» нь савлана

Хоёр машин ижил DWG-г **өөр замаар** барьж, хоёулаа экспортлобол
`nativeDocumentPath` **ээлжлэн солигдоно**. Зам нь зөвхөн харуулах ба
дахин холбоход хэрэглэгддэг тул **хор хөнөөлгүй** — гэхдээ «зам
шинэчлэгдэв» тэмдэглэл нь **тасралтгүй чимээ** болно.

Тиймээс:

> Тэмдэглэл нь **энэ төхөөрөмжийн харснаас** өөрчлөгдсөн үед л гарна.
> Сүүлд зарласан утгыг санаж, давхардсаныг дарна.

Мөн талбарын утга нь гэрээнд **«сүүлд харагдсан зам»** гэж нэрлэгдэнэ —
«эх үүсвэрийн байршил» биш. [[store-facts-not-conclusions]]: түүхий
ажиглалт хадгалагдана, дүгнэлт биш.
